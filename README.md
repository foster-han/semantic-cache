# semcache

分层语义缓存的 SDK 与验证台。

```
sdk/    @jolli.ai/semantic-cache —— 零依赖 TypeScript 库，端口化，可接入任何 RAG 应用
lab/    本地验证台 —— 带标注的场景集 + 对照实验 + 模型判别力自检（真模型，可离线跑）
docs/   《语义缓存的精度层》文章源文件
```

存储有内存、pgvector、Redis 三个实现，选哪个是一个环境变量的事；判定逻辑与存储无关，
几种后端跑同一份场景集必须得到同样的数字（`lab/scripts/storeConformance.ts` 把这句话
做成了可执行的）。

## 快速开始

```bash
# 验证台（首次会下载约 200MB 模型；MODE=stub 可零依赖秒起，但分数无统计意义）
cd lab && npm install && npm start          # 中文语料
cd lab && CORPUS_LANG=en npm start          # 英文语料
# → http://localhost:7788

# SDK 端到端冒烟（假模型，不下载任何东西）
cd sdk && node --experimental-strip-types example/Smoke.ts

# 换 pgvector（需要一个装了 vector 扩展的库）
createdb semcache && psql -d semcache -c 'CREATE EXTENSION vector'
cd lab && npm run start:pg
cd lab && npm run store-conformance

# 换 Redis（要 Redis 8 —— vectorset 在内核里，不用装 Redis Stack）
cd lab && npm run start:redis
cd lab && npm run store-conformance:redis
```

## 这套东西验证了什么

六道闸各管一类失效。截至目前实测立得住的结论：

| 结论 | 证据强度 |
|---|---|
| **⑥ 抓的是「问题侧看不出差别、检索结果却不同」的那一类** | 英文 13 条用例：全闸假命中 **0**，关掉 ⑥ 升到 **4**，多漏的正是同词不同指 ×2 + 实体塌陷 ×2。代价是复用 3→7 |
| **支撑度的算子比阈值更要紧** | 重心会稀释信号，取 max 会被旧答案自己的来源片段顶起来（Vapnik→Breiman 就这么漏的），**top-1** 才对。且标定与实现必须同算子 |
| 回答校验的检索必须用保留实体的原文 | 形态上稳定复现（关掉即失明），但**当前量化不可靠**：两条实体用例期望文档不同，随机撞中一条。此前三次"+2 精确落位"建立在已被推翻的个人成绩场景上，证据链作废 |
| **纯余弦分不开近义反义** | 英文问题对上 margin **−0.2936**：L1/L2（该拦）0.9214 > cross-validation 同义改写（该复用）0.6278。任何单一阈值必然同时犯两种错 |
| **任务错配会静默失效** | 两次实测：句对模型做检索，「什么是过拟合」top-1 是批归一化（0.366→换检索模型后 0.888）；段落重排器比问题↔问题，中文跨度 0.0013 |
| 资料版本比对有效 | 语料改版两条稳定被 ⑤ 拦下 |

| **⑥ 的判别力不依赖生成端，阈值依赖** | 同一组 10 条标定用例，换成 `claude -p` 真生成：margin 0.0348 → **0.0341**（几乎不变），但分布整体下移 ~0.017，建议阈值从 0.980/0.963 变成 **0.963/0.946**。算子对，阈值必须跟着生成端重标 |

尚未立住的：

- **13 条场景集测不出 θa 的差别**。三组阈值（0.97/0.96、0.980/0.963、0.963/0.946）
  跑出完全相同的结果。不是阈值不重要，是这个测试集的支撑度分布太两极 ——
  测阈值要用 `scripts/calibrate.ts` 的探针，不要用 bench。
- **④ 精排在本测试集上实测为负收益**。三段话一起才诚实：
  1. 探针层面，重排器把不可分（margin **−0.2936**）变成勉强可分（**+0.0344**）
  2. 端到端，开与关的假命中同为 0，但复用 **3（开）vs 5（关）** —— 零精度收益，砍掉 2 次合法复用
  3. 但测试集有盲区（见下），④ 的潜在价值被系统性低估
  准确的说法：**用一个任务错配的重排器（`ms-marco` 比问题↔问题），④ 是负收益；
  换成句对相似度训练的模型会怎样，没有验证过。**

> **一条已被推翻的旧结论**：先前两次说「课内跨章那两条六道闸没有一道够得着，只能靠 pre-filter」。
> 那是错的 —— 它们不是拦不住，是被 max 算子放过去了。换成 top-1 后 ⑥ 把两条都拦下，首要依据也都对。
> 我把自己的实现缺陷当成了机制的固有边界，这正是"算子错了比阈值错了更隐蔽"的实例。

## 已知的测试集盲区

判据是「答案的首要依据是不是那篇资料」。当两个概念**住在同一篇资料里**时，这个判据看不出错：

- `L1/L2` 两问都合法指向 n8（同一篇讲义讲了两者）
- `precision/recall` 两问都合法指向 n11

所以三条近义反义用例里有两条**无法被当前判据检出**，④ 的价值因此被系统性低估。要修就得把判据下沉到答案文本层面，或者把这类概念拆成独立文档。

> 设计架构图（分层 / 端口 / 读路径 / 打分器与阈值绑定）在 [`sdk/README.md`](sdk/README.md#设计架构)。

## 分层

```
应用
 └─ PII 层：检测 / 脱敏 / 还原 / 决定能不能跨主体共享   ← 在 SDK 之上
     └─ sdk/：只认 scope 与两份文本，不认识 PII
```

SDK 守住一条边界：**声明为已脱敏的请求，不允许落进共享 scope**（会抛错）。
验证台里 `declareRedacted` 开关就是在演示这件事 —— 关掉它（模拟上层忘了声明），
实体塌陷就能被配置出来，这时只能靠 ⑥ 兜底。

## 踩过的坑（都记在各自 README 里）

1. 用例最初是「怎么重置密码」「James Bond 是真人吗」—— 跟学生和学科资料没关系
2. 搭了六门课做跨课复用 —— 但一个学生只在一门课里，跨课复用不存在
3. 判据最初是「该不该重生成」—— 有干扰缓存后失效，命中另一条正确缓存也是成功
4. 判据改成「期望文档在依据里」—— 太松，把「复用过拟合的答案给问欠拟合的学生」判成通过
5. 三个模型角色共用一个模型 —— 任务错配，静默失效
6. 答案向量与检索片段跨向量空间比较 —— 余弦无意义
7. 换掉打分器却复用旧尺度的阈值 —— 对照实验因此无效
8. 改了 SDK 的 `Generate` 契约（新增必填 `kind`），无类型的验证台没跟上 —— 13 条全 `null`，静默降级不报错（已转 TypeScript 堵死）
9. ⑥ 的支撑度**标定用单篇文档、实现用 top-k 取 max** —— 阈值失效，还让我把实现缺陷写成了机制边界

第 5 和第 7 是同一件事的两面：**阈值属于打分器，不属于流水线**。换打分器必须连阈值一起重标。

第 9 更进一层：**算子选错比阈值标错更隐蔽**。阈值错了假命中率降不下来，还有征兆；
算子错了会让标定本身失去意义，然后你把自己的实现缺陷当成机制的性质写进结论。
