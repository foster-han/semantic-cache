语义缓存的精度层

上一篇选定了 Redis + pgvector 的两层缓存，也留下一句没有展开的话——「语义缓存是概率型缓存，每次命中都带『可能错』的概率」。这一篇讲怎么把那个概率压到能上线：不是把余弦阈值调高，而是四道各管一类失效的闸。

范围 LLM 响应缓存的正确性 承接 语义缓存后端选型 状态 提案

这篇是提案，不是当前实现（2026-09）。文中的六道闸现在只剩 ①②③④。第 ⑥ 道回答侧校验先移除——它管的两类失效（同词不同指、实体塌陷）源于缓存键有损，该在键和 scope 的构成上解决，而不是在答案侧兜底。第 ⑤ 道语料版本比对随后移除——它要求每个条目记下自己引了哪些文档（source_chunk_ids / corpus_version 这两列），而那整条维度已经拆掉：条目现在只记它属于哪个 space，「资料改版了」由清掉那个 space 来处理，读路径上没有任何一道闸看得见改版。下文关于 ⑤ ⑥ 的论证与实测都仍然成立，请读成历史记录；代价的明细在 FINDINGS.md 顶部两节。

Decision

精度不是一个阈值，是四道各管一类失效的闸

  • 问题侧要不要精排，取决于你有没有任务匹配的模型。句对相似度训练的重排器才对；拿段落检索的重排器来比「问题↔问题」是任务错配——实测端到端是负收益（零精度提升，砍掉 2 次合法复用）
  • 过期靠语料版本比对，不靠相似度。余弦分不出「同主题」和「仍成立」——讲上学期大纲的旧答案，和更新后的大纲片段，余弦依然很高
  • 回答侧校验抓的是「问题侧看不出差别、检索结果却不同」的那一类——实体塌陷与同词不同指都在其中。13 条用例上关掉它，假命中从 0 升到 4，代价是复用次数从 3 涨到 7
  • 支撑度用哪个算子，比阈值定在哪更要紧。对 top-1 片段比，不是对 top-k 取 max、也不是取重心——而且标定与实现必须用同一个算子，否则标出来的阈值根本不适用

前提：先吃满零假命中风险的省钱手段。语义缓存在成本杠杆里排第四顺位，也是唯一一个会给用户错答案的。

先说顺位：语义缓存不是第一个该动的杠杆

上一篇把「缓存后端选哪个」讨论透了，但没讨论「缓存是不是该先动的那件事」。把成本杠杆按风险排一遍，语义缓存排在最后：

杠杆省什么假命中风险前置条件顺位
Provider prompt caching 每次调用的输入 token 无 — 字节前缀精确匹配 出口透传 cache_control 先做
L0 精确缓存 整次调用（字面重复） 无 — 哈希相等 已在上一篇落定 先做
头部问题策展 QA 整次调用，且答案质量更高 无 — 人工审过 需要策展流程与责任人 先做
语义缓存 整次调用（长尾改写） 有 — 概率型 本文这四道闸 第四

Prompt caching 为什么排第一

辅导场景的请求形状，恰好是前缀缓存的教科书案例：一大块固定的 system 指令加课程上下文，后面接每次都变的检索片段和问题。缓存读约 0.1× 输入价；写入 5 分钟 TTL 是 1.25×、1 小时 TTL 是 2×——两次请求就回本（1 小时 TTL 需三次）。而它是字节级前缀匹配，不存在「差不多就算命中」这回事，假命中风险为零。

一个会静默烧钱的陷阱：断点必须打在共享前缀的末尾，不能打在整个 prompt 末尾。打错位置的话，每次请求都写一条新条目、永远读不回来，纯付 1.25× 的写入溢价。判断方法只有一个：看 cache_read_input_tokens 是不是长期为零。

策展 QA：上一篇自己写了，然后走过去了

上一篇在讨论 RAGFlow 时留了一句：「真要给高频重复问题便宜地出好答案，正解往往不是缓存，而是 RAG over 一个可策展的 QA 知识库」。辅导产品的问题分布是课程绑定、高度可预测的——头部那几十个问题策展一次、审过一遍、确定性返回，比概率型缓存更便宜也更准。语义缓存该去吃的是长尾，不是头部。

还有一类问题根本不该进这条管线

「李四的作业二得了多少分」不是 RAG 问题。它是一次结构化查询 + 授权检查，正确路径是意图路由送去工具、由授权层判定学生 A 无权查学生 B——LLM 和缓存都不该看见它。把个人数据放进可检索语料本身就是架构错误；PII 门控和回答校验都只是在替这个错误打补丁。

而这类问题同样需要语义缓存，只是缓存的东西不同：贵的是 LLM 判断「该调哪个工具、传什么参数」，工具调用本身很便宜。所以这一支缓存计划，不缓存结果——实体是计划里的参数，执行时用当前请求的实体填、当场做授权。

于是占位符塌陷在这一支从灾难变成了收益。「张三的…」和「李四的…」脱敏后塌成同一个键，正好共用同一条 getGrade(student=$1, assignment=2) 计划，塌得越彻底命中率越高。危险的从来不是塌陷本身，而是缓存了含实体特定内容的答案。

所以判据不该是「有没有脱敏」，该是缓存的是什么：answer 条目脱敏后不能跨主体共享，plan 条目可以且应该。

只看问题相似度，会漏掉三类失效

把 bi-encoder 的余弦分当唯一判据，等于假设「问题像 ⇒ 答案能复用」。这个假设在三个地方破掉，而且破法各不相同——这正是为什么一个阈值调不出来。

失效 A

意图之差

公开评测记录了：只在时间范围、极性、分析意图上不同的 query，余弦常常超过 0.95。「这学期的截止日期」和「上学期的截止日期」在 bi-encoder 眼里几乎是同一句话。

失效 B

语料改版

课程大纲、讲义、评分标准换了版本，缓存里的旧答案引用的还是上一版。问题本身没变，变的是它底下的语料——问题侧再怎么比都看不出来。

失效 C

占位符塌陷

上一篇的 <PERSON_1> 问题：匿名化之后两条 prompt 字面完全相同。相似度是 1.0，不是 0.95——任何问题侧方法在这里都是自信地错。

三类失效需要三种不同的证据：A 需要更强的语义判别力，B 需要语料的版本事实，C 需要被匿名化销毁的实体信息。指望一个余弦阈值同时管住三件事，只能得到一个既漏又误的中间值。

六道闸

整条读路径是一串闸门，每道闸只放行它有把握的那部分，失败的一律汇到同一条回落轨——完整生成。注意第 ③ 道：召回必须取 top-5 而不是 top-1，否则第 ④ 道无处可插。

④ Cross-encoder 重排：值不值，取决于模型任务匹不匹配

bi-encoder 把问题和缓存条目各自独立编码成向量再比余弦——它从来没有同时看过这两句话。cross-encoder 反过来，把两句拼在一起送进模型，让注意力直接在两者之间跑。差别就在这里：极性、时间范围、分析意图这些「一个词的差别」，bi-encoder 摊平在向量里看不见，cross-encoder 看得见。

最后一行值得说明，因为它是这份提案的第一版方案，被自己推翻了。「摘要 ↔ 片段余弦」的成本论述有个洞：读路径确实零 LLM 调用，但写路径每次 miss 都要生成一次摘要，而 miss 恰恰是本来就最贵的那条路径。更要命的是它测的是「同主题」不是「仍成立」——失效 B 里，旧答案和新片段主题完全一致。

但「加个 cross-encoder」这句话不够

写完这篇之后我搭了个本地原型跑这套流程，第一次用真模型就翻车了：对照组「什么是递归？」的缓存被「什么是闭包？」命中。逐闸看下来，是 ④ 放的水——重排器给这两句打了 0.998。

拿四组难度递减的问题对去探它，问题就清楚了：

问题对中文 sigmoid英文 sigmoid
同义改写0.99880.0296
同主题不同问0.99840.0001
完全无关0.99750.0000
跨度0.0013~0.03

两件事，第二件更要紧：

  • 中文上完全饱和。这个重排器是英文训练的，中文输入下输出恒为 ~1.0，跨度 0.0013——没有任何判别力
  • 即使在英文上，任务也是错的。排序方向对（同义 > 无关），但绝对值全压在 0.03 以下。因为 ms-marco 是 query→passage 的相关性模型，而语义缓存要比的是 query→已缓存的 query——那是句对相似度，不是段落检索。任何固定 θq 在这种压缩分布上，要么切掉全部要么放过全部

所以上面那些 96–98% 的公开数字，是段落重排基准上的，不能直接搬到问题配对上。任务匹配的选择是句对 / 重复问题训练的 cross-encoder——GPTCache 的 evaluator 用的正是 Quora 问题对训练的模型，这个细节此前被我读漏了。

由此得到一条该写进上线清单的规则：信任任何重排器之前，先测它的判别力。给它三组难度递减的问题对（同义 / 同主题不同问 / 完全无关），看分数跨度。跨度小于 0.15 就说明模型和任务不匹配，此时这一层的任何离线标定结果都是无效的——你标定的是一个常数。这一步花不了十分钟，能省掉一整轮白跑的标定。

端到端实测：这个重排器是负收益

探针层面的证据是硬的：英文问题对上，纯余弦 margin −0.2936（L1/L2 该拦的 0.9214，比 cross-validation 该复用的 0.6278 还高，任何单一阈值必然同时犯两种错），加上重排器之后 margin +0.0344——把不可分变成了勉强可分。

但端到端跑 13 条用例，结论反过来：

配置假命中通过复用次数
④ 精排开（θq 0.979）013/133
④ 精排关（问题侧只剩召回下限）013/135

一条假命中都没多拦，却砍掉了 2 次合法复用。原因和探针结果是一致的：ms-marco 对「问题↔问题」任务错配，把同义改写也压到了 θq 之下。

这个对照本身也修过一次。第一版是无效的：关掉精排时代码退化成「拿 θq 去卡召回余弦」，而 0.979 是重排器的 sigmoid 尺度，套到余弦上严到荒谬。阈值属于打分器，不属于流水线——后来把这条退化路径整个删掉，「没有重排器就是没有这道闸」，对照才有效。

三段话一起才是诚实的：① 探针层面，重排器把不可分变成了勉强可分；② 端到端，它砍掉 2 次合法复用、零精度收益，是纯负收益；③ 但测试集有已知盲区——三条近义反义用例里有两条的两个概念住在同一篇讲义里（L1/L2 同属一节，precision/recall 也是），把 L1 的答案复用给问 L2 的学生，「首要依据」这个判据看不出错，④ 的潜在价值因此被系统性低估。

所以准确的说法是：用一个任务错配的重排器，④ 是负收益；换成句对相似度训练的模型会怎样，没有验证过。「④ 是主精度杠杆」这句话目前只有探针证据。

上一篇有一行需要改

落地架构那段 SQL 直接 LIMIT 1 取最近邻一条，等于在结构上放弃了重排层——没有候选集，就没有东西可排。

-- 上一篇：只取最近邻一条，重排无处可插
SELECT response, embedding <=> $3 AS distance
FROM   semantic_cache
WHERE  tenant_id = $1 AND model = $2 AND expires_at > now()
ORDER  BY embedding <=> $3
LIMIT  1;   ← 改成 5

-- 改后：召回 5 条交给重排器，精度从 bi-encoder 的天花板上抬起来
-- 应用层不再直接判 distance，改判重排分
LIMIT  5;

顺带一处张力，建议量一次再定。上一篇的判据 02 是「每次 miss 都写一条，是持续的高频单条写」，却选了 pgvector 里插入最贵的 HNSW（每次插入要走图、更新邻居）。而 WHERE tenant_id + model + expires_at 过滤之后，候选常常只剩几千行——这个规模下顺序扫描算 <=> 是亚毫秒且精确的。HNSW 在这张表上有可能是净负收益，值得在真实数据量上量一次再决定要不要建。

置信带：一个阈值不够，要两维

重排分高，只说明「问的是同一件事」；还要问「那个旧答案现在还立得住吗」。两个维度切出四个区域，而不是一条线切出命中/不命中——中间那条带就是「微调复用」的容身之处：旧答案加新片段做一次短生成，token 远少于从零生成。

⑤ 语料版本：过期不该问相似度

失效 B 的本质不是「答案和语料不像」，而是「答案是另一个版本的语料生成的」。这是一个可以直接查的事实，不需要推断——所以别用相似度去猜它。

  • 写入时记账 —— 缓存条目存下当时命中的 source_chunk_ids 和 corpus_version
  • 读取时比对 —— 版本号不等于当前 scope 的语料版本，直接判失效并 evict，不算相似度
  • 更新时批量失效 —— 课程材料重新入库就是一次事件，一句 DELETE 把该 scope 下旧版本的条目全清掉
  • TTL 仍然保留 —— 上一篇的 expires_at 是兜底，管的是「没有任何事件但答案就是老了」那部分

这条也是行业里 RAG 缓存失效的标准做法：TTL 打底、文档更新事件驱动、corpus version tag 做判据。没有人用相似度判过期，因为它判不出来。

⑥ 回答侧校验：治「问题侧看不出差别」的那一类

上一篇新增的那一节把跨学生串答案的入口堵住了：Presidio 检出实体就强制 user-scope，占位符选会话随机，跨学生命中只发生在压根没有 PII 的那批 prompt 上。这是确定性的门控，是第一道防线。

但门控是按「有没有检出实体」判的，而检测器有漏检；一旦漏了一个实体，两条本该分开的 prompt 就在 <PERSON_1> 上塌成同一条。这时候问题侧已经没有任何信息可用了——两个字符串一模一样，cross-encoder 给 1.0，余弦给 1.0。信息在匿名化那一步就被销毁了。

唯一还活着的证据：这次检索到了什么

生成之前当然没有「当前答案」，但有一个便宜且已经要算的东西——这次检索到的文档片段。用它当「当前答案语境」，问题就从「新旧答案像不像」变成了「旧答案还被现在的语料支撑吗」。

学生②问的是 Obama，检索命中的是 Obama 相关片段；缓存里那条旧答案的向量说的是「虚构角色 / 007 特工」。两者相似度极低 → 判失效 → evict → 走完整生成。实体信息虽然从问题里被抹掉了，却从检索结果里绕回来了。

三条边界，缺一条这层就白做

  • 检索必须在匿名化之前。如果检索也跑在匿名化后的文本上，两个学生检出的是同一批片段，这一层完全失明——它拦不住任何东西。这是整层成立的硬前提
  • 不替代 Presidio 门控。门控确定性、在入口挡；这层概率型、在出口兜。纵深防御的第二道，不是第一道的替代品
  • 不当通用精度杠杆，也不当过期检测。那是第 ④ 和第 ⑤ 道闸的活。派它去干那两件事，就会得到本文开头推翻的那个方案

它实际抓住了什么（实测）

13 条用例、全闸打开时假命中 0；单独关掉 ⑥ 升到 4。多漏的那四条分成两类，而它们有一个共同点：

  • 实体塌陷 ×2 —— 「Hinton 提出了什么方法」与「LeCun 提出了什么方法」，匿名化后字面相同
  • 同词不同指 ×2 —— 「归一化」在特征工程章是特征缩放、在网络章是批归一化；「收敛」在优化章与 EM 章各指一事

共同点是：问题侧看不出任何差别，检索结果却完全不同。这才是 ⑥ 的准确定位——不是"专治实体塌陷"，实体塌陷只是这一类里最刺眼的一个例子。凡是「问题文本相同或极近、但语境把答案指向了别处」，都归它。

代价要一起写：开着 ⑥ 复用 3 次，关掉复用 7 次。精度归零的代价是命中率减半。这个取舍必须在你自己的流量上量，不能照搬。

支撑度怎么算 —— 算子比阈值更要紧

「旧答案是否仍被检索片段支撑」这句话要落成一个具体算子，而三种写法差别巨大。我先后写错两次：

算子语义失效方式
对 top-k 取重心「和这批片段整体像不像」片段少时无关的也被捞进来，平均后信号被稀释
对 top-k 取 max「有某个片段撑得住旧答案」旧答案自己的来源片段常常还在 top-k 里，跟自己比当然高分，max 被它顶起来
对 top-1 比「旧答案和现在会据以回答的那篇一不一致」—— 选用

取 max 那次的教训特别具体：问「Breiman 提出了什么方法」，检索回来的三篇里仍含 Vapnik 那篇，而缓存答案正是从它生成的，于是支撑度被自己的来源顶到高位，塌陷放行。

更隐蔽的是它会让标定失效。我标定时拿「答案 ↔ 单篇文档」比、实现却取 top-k 的 max——标定与实现不是同一个算子，标出来的阈值根本不适用。而后果不是报错，是我把「课内跨章这两条谁也拦不住」写成了机制的固有边界，直到换成 top-1 才发现它们一直是拦得住的。

阈值标错了还有征兆（假命中率降不下来）；算子选错了会让标定本身失去意义，然后你把自己的实现缺陷当成机制的性质。

成本：存答案向量，不存摘要

写入时直接 embed 答案原文（或前 N token），不生成摘要——省掉每次 miss 一次 LLM 调用，只多一次 embedding。读路径则是已存向量与本次片段向量的一次点积，接近零边际成本。整层换来的是：把「静默返回错答案」换成「多花一次检索」。

读路径

函数 应答(query, user, course):
    scope ← Presidio.检出实体(query) ? user 域 : course 域        ① 门控

    若 命中 ← L0.精确查(hash(归一化(query)), scope):             ② 字面重复
        返回 命中.answer

    候选 ← 向量库.近邻(embed(query), scope, top_k = 5)          ③ 召回，不是 1
    若 候选 为空: 返回 完整生成(query, scope)

    最佳 ← 重排器.打分(query, 候选).取最高                        ④ cross-encoder
    若 最佳.分 < θq: 返回 完整生成(query, scope)

    若 最佳.corpus_version ≠ 当前语料版本(scope):               ⑤ 确定性判据
        缓存.驱逐(最佳)
        返回 完整生成(query, scope)

    片段 ← 检索(query.保留实体原文, scope)                        ⑥ 注意：匿名化之前
    支撑度 ← 余弦(最佳.answer_embedding, 片段.向量重心)               本次请求内复用这批片段

    若 支撑度 ≥ θa_高: 返回 最佳.answer                        直接复用
    若 支撑度 ≥ θa_低: 返回 短生成(最佳.answer, 片段)           微调复用
    缓存.驱逐(最佳)
    返回 完整生成(query, scope, 片段)

函数 完整生成(query, scope, 片段 = 无):
    片段 ← 片段 ?? 检索(query.保留实体原文, scope)
    答案 ← LLM(prompt(片段, query))
    缓存.写入(答案, embed(答案), 片段.ids, 当前语料版本(scope), scope)  无摘要生成
    返回 答案

表结构增量

不新建表，在上一篇的 semantic_cache 上加列。scope 相关列沿用 E7-2 已有的定义。

ALTER TABLE semantic_cache
  ADD COLUMN answer_embedding vector(1536),   -- ⑥ 答案原文向量，不是摘要
  ADD COLUMN source_chunk_ids TEXT[],         -- ⑤ 写入时命中的片段
  ADD COLUMN corpus_version   TEXT,           -- ⑤ 语料版本快照
  ADD COLUMN hit_count        INT NOT NULL DEFAULT 0,
  ADD COLUMN last_verified_at TIMESTAMPTZ;    -- 观测：上次通过 ⑤⑥ 的时间

-- ⑤ 语料改版时批量失效：一句 DELETE，不用逐条算相似度
CREATE INDEX ON semantic_cache (scope, scope_id, corpus_version);

answer_embedding 不建向量索引。它只被「已经被重排选中的那一条」用到，是点查不是检索——建 HNSW 只会给这张高频写入的表再加一份维护成本。

算子要写进契约，别留给实现者猜。支撑度 = cosine(answer_embedding, embed_passage(top_1_chunk))，对 top-1 片段比。同样重要的是：answer_embedding 必须由检索模型的 passage 侧编码，才能和检索片段落在同一个向量空间——用句对模型编码答案、用检索模型编码片段，算出来的余弦没有任何意义。

阈值怎么定，怎么灰度

上一篇说了「阈值别拍脑袋，用真实历史 query 离线标定」，这里给流程。行业做法可以照搬：

  • 取样标注 —— 从生产日志抽 100–500 条真实 query，人工标注每条「正确的缓存行为」应该是什么
  • 画曲线定阈值 —— 在这批数据上跑出 precision / recall 曲线。生产阈值普遍落在 0.7–0.95，具体值取决于语料和 embedding 模型，没有可移植的默认值
  • 上线门槛 —— precision ≥ 95% 再放量。两类错误代价不对称：miss 只是浪费一次调用，假命中是给学生错答案
  • Shadow mode 先行 —— 先只记录判定结果、不真的复用，用真实流量对齐离线标定，再逐步放开
  • 三个阈值分开标 —— θq（重排）、θa 高、θa 低 各自标定。θa 低那条决定「微调复用」这条带有多宽，标错了要么白花短生成的钱，要么放过该重生成的条目

上线后要盯的

命中率不是主指标，假命中率才是。至少要能分开看：④ 重排拒绝率、⑤ 版本失效率、⑥ 回答侧拒绝率。三条曲线的形状会直接告诉你哪类失效在涨——⑤ 陡增说明语料在频繁改版，⑥ 陡增则要去查 Presidio 的漏检率。

沉淀下来的判断

  • 一个阈值管不了三类失效。意图之差要判别力，语料改版要版本事实，实体塌陷要被销毁的信息——证据类型都不同，硬凑成一个余弦分只能得到一个既漏又误的中间值
  • 能查事实的地方别用相似度推断。语料版本是可以直接比对的事实，用余弦去猜它，恰好在「同主题但不同版本」这个最常见的情形上失明
  • 成本论述要把写路径算进去。「读路径零 LLM 调用」听起来漂亮，但如果写路径每次 miss 多一次生成，省的钱正好花在最贵的那条路上
  • 纵深防御不等于重复防御。Presidio 门控和回答侧校验都在处理跨学生串答案，但一个在入口确定性地挡、一个在出口概率性地兜。能说清各自不管什么，这层才有存在意义
  • 一个任务错配的打分器，比没有这个打分器更糟。它不是"效果差一点"，是既不提升精度又砍掉合法命中——加一层之前先证明它在你的数据上能拉开分
  • 算子选错比阈值标错更隐蔽。阈值错了假命中率降不下来，还有征兆；算子错了会让标定本身失去意义，然后你把自己的实现缺陷写成机制的固有边界。标定与实现必须是同一个算子
  • 阈值属于打分器，不属于流水线。换掉一个打分器，它的阈值必须一起重标。拿重排器尺度的阈值去卡余弦，会造出一个看起来正常、实则严到荒谬的对照实验
  • 先看数据该不该在这条管线里。个人数据不进可检索语料，工具类问题缓存计划而非结果——很多看似需要缓存层解决的安全问题，其实是路由与数据布局的问题
  • 先吃满零风险的省钱手段。prompt caching、精确缓存、头部策展都不会给出错答案。语义缓存是唯一带假命中的那层，它该最后上，也该被要求给出精度证据

本文的第 ④ ⑥ 节与表结构一节都经过本地原型验证并因此被修正过：原型跑通了 ⑤ ⑥ 两层的预期行为（关掉 ⑥ 后占位符塌陷立刻放行；把检索改到匿名化之后，⑥ 只对实体塌陷失明而对课程语境仍有效），但在 ④ 上发现了上面那个任务错配。⑥ 的实现过程中先后改正三处：语料指纹应按引用文档而非整门课来算；支撑度的算子从重心改成 max、再改成 top-1（前两次都会让塌陷漏网，且第二次让我误把实现缺陷当成机制边界）；答案向量必须由检索模型的 passage 侧编码。

最终一轮英文实测（13 条用例，单门课，含 30 条干扰缓存）：全闸打开假命中 0、复用 3；关掉 ⑥ 假命中 4、复用 7。测试集有已知盲区：两个概念住在同一篇资料里时，「首要依据」这个判据看不出错，④ 的价值因此被系统性低估。
